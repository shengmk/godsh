# godsh v0.7.1

godsh — DeepSeek Harness 的图形化环境配置启动器与电影级控制中心（双模主题 · 动态极光 · 无控制台启动）。

> **这一版把「插件沙箱」搬进了 dsh，并且让「注入」变成即时的。**
> 在 dsh 的设置页里，你现在可以看沙箱、把插件注入到某个环境、移除、检查更新、收割环境、回收空间。
> 点下「注入并热装载」之后，插件**当场**进入正在运行的这个 dsh ——
> **不重启进程、不刷新页面、对话不中断**。
>
> 这一版还修掉了一个**会让环境直接打不开**的真缺陷。它是我在开发过程中
> 真的把测试环境搞到起不来才发现的 —— 也正因为如此，它很可能也会发生在你身上。

## ✨ 在 dsh 里管理沙箱

设置页新增 **「godsh 插件沙箱」**，从自检面板升级为一个真正能用的页面：

- **状态头**：沙箱数据目录（并说明"为什么是这个目录"）、当前运行环境、条目数
- **工具条**：刷新 / 检查更新 / 收割环境 / 回收空间
- **条目列表**：按父折叠，带**来源徽章**（npm 包 / 自环境收割 / 本地目录导入 / 按父隔离副本）、
  可更新标记、已注入环境、体积；子依赖没有独立操作入口（它们随父一起进出），
  父已缺失的孤儿条目会明确标注而不是被隐藏
- **逐条操作**：注入并热装载 / 更新 / 移除（两步确认，防误删）

**数据目录与启动器完全一致**（`DSH_LAUNCHER_DATA_DIR` → `%APPDATA%\godsh\data` → `$DSH_HOME/godsh/data`）。
这一点必须一致：否则你在 dsh 里看到的就是**另一份空沙箱** ——
那不是"在 dsh 里管沙箱"，而是"又造了一个沙箱"，而且几乎不可能被肉眼发现。

## ⚡ 「注入」= 四阶段，且如实告诉你生效范围

```
① 预检      目标环境与物理源是否就位
② 物理挂载  Junction 零拷贝 + package.json 声明 + bundles 门控（失败自动回滚）
③ 写补丁层  与启动器分配页**同一条**路径
④ 热装载    目标就是本进程所在环境 → 直接进运行树；否则明确告诉你"需启动该环境"
```

界面上用**四种不同措辞**显示结局：`已生效` / `需启动该环境` / `已挂载但未声明` / `失败`。
把"没有完全生效"含糊成"成功"，正是这个项目一直在打的那类问题。

**实测数据**（可复现脚本随仓库发布）：

| 观测 | 结果 |
|---|---|
| 运行树条目数 | **157 → 158**（新插件真的进了当前进程） |
| 客户端模块图 | **54 → 55**（浏览器半也被纳入可服务图） |
| **dsh 进程 PID** | **全程未变**（没有重启） |
| 移除之后 | 补丁层与运行树**都**回到干净状态 |

## 🩹 一个会让环境「直接打不开」的缺陷，已修

**现象**：把插件从沙箱移除后，环境下次启动直接失败：

```
failed to apply loader entry include (cordis:include):
failed to import loader entry <包名> (undefined): Cannot read properties of undefined (reading 'startsWith')
```

**根因**：移除时沙箱只解除了环境里的链接与 `package.json` 声明，它**不认识「分配层」**。
而上一版引入的「安装即启用」会让注入同时写 `<profile>/cordis.patch.yml` ——
于是移除后那一行成了**悬空行**：声明了一个已经不存在的插件，dsh 装载阶段直接崩。

**修法**：让注入与移除在声明层上**对称**，并接入全部四个移除出口；
dsh 内那一侧还会顺带把运行树里的条目**热卸载**（注入是即时的，移除也必须即时）。

**配套工具**：仓库里新增了 `scripts/exp/fix-dangling-patch-rows.mjs`，
可以扫出所有环境的悬空补丁行并 `--fix` 清理 —— 我用它把自己搞坏的环境修好了。
它也会**拒绝**改写含嵌套配置或 `!!js` 表达式的补丁文件并说明原因，
而不是"顺手"重写你的配置。

## 🔧 另外修掉的

- **一个我自己造成的 bug**：插件里以为 `ctx.baseUrl` 是路径，实际它是 `file://` URL，
  于是拼出了 `.\file:\C:\Users\...` 这种垃圾路径，导致注入预检误报「目标环境不存在」。
  这条是**端到端实测**抓出来的，不是读代码想出来的 ——
  也说明"看起来对"和"跑起来对"是两件事。
- 清掉了 7 个源文件里的 UTF-8 BOM（BOM 会让带 shebang 的脚本直接语法报错）。

## 🧭 这一版**没有**做（如实登记）

- **影子校验**（先在一个一次性实例里试跑，坏插件根本进不了你和 dsh 的对话）——
  仍未实现。目前"坏插件"只能靠事后移除 + 补丁层清理来收拾。
- **原生热重载后端**（上游那条通道在本机不生效）、
  **交接式重启**（进程换了但对话续上）——都未实现。
- 安装版的「本地插件」列表仍为空：打包流程从不复制 `resources/plugins`
  （既有的低危空白，一直如此）。
- 有一条端到端单测依赖公共 npm registry，网络抖动时会偶发失败。

## 升级建议

直接覆盖安装即可，环境与配置不受影响。

**如果你之前用 v0.7.0 从沙箱移除过插件**，建议跑一次仓库里的
`scripts/exp/fix-dangling-patch-rows.mjs` 检查有没有留下悬空补丁行
（默认**只检测不修改**；加 `--fix` 才清理）。这是 v0.7.1 修掉的那个缺陷的**遗留状态**。
