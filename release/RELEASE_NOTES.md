# godsh v0.6.3

godsh — DeepSeek Harness 图形化环境配置启动器与电影级控制中心（双模主题 · 动态极光 · 无控制台启动）。

本次是**无障碍与设计令牌专项**版本：把深浅两套主题下的文本对比度**全站做到 WCAG 达标**，修掉一个让浅色主题静默用错颜色的级联缺陷，并补上了「能在真实浏览器里测量 UI」的工程能力。**没有破坏性变更，配置与环境数据可直接沿用。**

## ♿ 对比度：全页面扫描 26 类不达标 → 0

用真实浏览器遍历**每个页面、每个主题下所有自带文字的元素**（198 → 207 种不同文字样式），按 WCAG 逐条测量。改前有 **26 类不达标**，最严重的几处：

| 原问题 | 实测对比度 | 影响面 |
|---|---|---|
| 浅色主题的次要文字（`#94a3b8` 对近白底） | **2.51:1** | 44+ 个元素 |
| 深色主题下的品牌色文字（含两处写死的 `#4f46e5`） | **2.61:1** | 59 个元素 |
| 琥珀底按钮配白字（深色 / 浅色） | **2.15 / 3.19** | 40+ 个元素 |
| 浅色主题的危险按钮文字（`#fca5a5`） | **1.67:1** | 删除类操作 |

改法（令牌级，不逐处硬编码）：**把「文字色」与「填充色」显式分开**，并采用「强调色必须配强调色前景」的配色约定——

- 新增 `--brand-text`（浅色 `#4f46e5` / 深色 `#818cf8`）：品牌色**当文字**用（6.15:1 / 5.25:1）；
- 新增 `--warn-surface` + `--on-warn`：琥珀**实底**配近黑前景（**8.3:1**）；
- 新增 `--brand-surface` + `--on-brand`：品牌实底配白字（6.29:1）；
- 按实测重取深浅两套的 `--text-muted` / `--muted` / `--text-secondary` / `--ok` / `--warn` / `--err`；
- 清掉 17 处硬编码或错用的颜色（`#4f46e5`、`#fca5a5`、`#34d399`、`color: var(--brand-1)`）。

**结果：全页面扫描 0 不达标**，深浅两套主题都无回归。

## 🎨 设计令牌治理

**修复「浅色主题的沙箱紫色被深色值覆盖」**：`--vault-*` 曾被定义 3 次，其中一处是文件后段的第二个 `:root`；
它与 `[data-theme='light']` **特异性相同（0,1,0）**，而位置更靠后 —— 于是浅色主题静默用上了为深色调的紫色。
已把令牌按作用域归位（基座 / 深色 / 浅色各只有一块），并用无头浏览器**实测计算值**确认：
浅色由 `#9333ea` 纠正为 `#7c3aed`，深色与默认主题取值前后完全一致。

同时新增**令牌回归测试**，把「基座 `:root` 唯一、主题作用域不被更靠后的 `:root` 覆盖、每个主题只有一块令牌」
变成可持续守住的断言——这类缺陷以后会在 `pnpm test` 里当场失败。

## 🔬 工程质量：能在真实浏览器里测量 UI 了

新增一套浏览器实测工具（此前只能读源码推断，容易看走眼）：

- `scripts/probe-browser.mjs`：用 CDP 驱动真实浏览器、设视口、注入脚本、取回结构化结果；
- 对比度**定向审计**与**全页面扫描**（不预设选择器，按失败样式去重）；
- **布局审计**：横向溢出 + 元凶元素清单 + 长列表统计；
- **字体审计**：用宽度对比法判断字体是否真的生效（比布尔型 API 可靠）。

实测结论：

- **横向滚动：1024×768 / 1280×800 / 1920×1080 / 3840×2160 四种分辨率 × 9 个页面全部为 0**；
- **长列表**：沙箱 59 行、市场 60 张卡片一次性渲染（桌面端可接受；已记录「单容器超约 150 行或页面 DOM 超约 12000 节点」时再引入虚拟化的阈值）；
- **字体**：页面无 `@font-face`、无网络字体请求，因此不存在 webfont 阻塞渲染问题；但实测发现界面声明的
  Inter / JetBrains Mono / Geist Mono **在本机全部回退**为 Arial 与通用等宽 —— 该问题已明确记录，
  下一步可选择内嵌 Latin 子集（约 100 KB、OFL 许可，中文仍走系统字体）或改字体栈。

> 一个诚实的说明：本轮的对比度测量工具**自己修过两次模型错误**（先是把元素自身的渐变背景漏出基准，
> 导致白字被拿去比白底、算出 1.10 这种假失败；后是在自下而上的合成循环里遇到不透明层就提前跳出）。
> 修正后才得出 `.btn.primary` 深色 10:1、浅色 5.7:1 的正确结论。**先怀疑尺子，再下结论。**
