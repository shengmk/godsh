## 🐛 七项缺陷根除（用户可见现象 → 根因）

### 1. 版本号漂移：安装包自报旧版本
安装包对外自报的版本来自代码里散落的硬编码字面量，导致新版安装包自称旧版本。
**现在**：建立版本唯一真源 `packages/core/src/version.ts`，构建期由 `scripts/build-server.mjs` 注入，并新增 `pnpm verify:version` 一致性守卫（4 项断言）接入构建流程。

### 2. 沙箱注入后环境打不开 / 闪退（最高危）
注入过程先建 `node_modules` 链接、最后才覆盖 `package.json`，中间存在「物理存在但未声明」的窗口，且无原子写、无锁、无注入后校验。
**现在**：改为「干跑校验 → 原子注入 → 注入后校验 → 失败回滚」；拒绝自引用、拒绝沙箱内不存在的包、按版本精确匹配，`bundles` 只在真的可解析时才写入，失败会明确告知原因而不是静默留下坏环境。

### 3. 删除子插件后环境打不开
伴随子插件会被写进环境声明，而删除时不清理声明、不解除挂载，之后启动就失败。
**现在**：加入反向依赖查询与删除保护——被别的插件依赖时**拒绝删除并列出依赖它的插件**；启动前还会拦截无法解析的 bundle。另新增「从插件自身 `package.json` 推导子依赖」，父子插件一起装全。

### 4. 沙箱插件删不掉 / 没有批量删除
删除只从索引里摘掉记录，不卸挂载、不删物理目录；前端还忽略失败结果，表现为「点了没反应但列表里没了」。
**现在**：删除改为完整事务（清索引 + 卸载挂载 + 按需删物理目录），失败不再静默并给出真实原因；新增批量删除（可勾选多个一次删）。垃圾回收改为「先扫描仍被引用的目录再删」，不再制造死链。

### 5. 快速启动链接丢 Token，打开就是 401
启动接口立即返回，而认证地址要等 dsh 输出才出现，前端在拿到之前用「`http://127.0.0.1:端口`」兜底，于是必然给出一个打不开的链接。
**现在**：全链路不再伪造地址——地址未就绪时明确提示，就绪后才给出带 token 的链接；后端支持等待就绪（`?wait=<ms>`）。

### 6. 部分点击无响应
三个叠加原因：所有失败（含 400/404/409 这类确定性错误）都退避重试约 13.7 秒；端口探测用同步子进程把单线程 API 服务冻结数十秒；大量按钮没有忙碌态、失败静默。
**现在**：4xx 立即返回不再重试、非幂等请求绝不重发；同步子进程调用全部改为异步并加缓存；统一「按钮置忙 + 真实错误提示」的操作反馈契约（全站 24 处）。

### 7. 每个页面都缺刷新
没有全局刷新，部分页面甚至完全没有刷新入口。
**现在**：顶栏新增全局刷新按钮（一键刷新所有页面），页面重新进入且数据过期时自动刷新该页，9 个页面全部接入。

## ⚡ 性能

- **残留进程反查重写（本次最意外的发现）**：原先「按 Profile 全系统反查」的查询串在 Windows PowerShell 下存在转义错误，**整条命令根本无法执行**，而调用处把异常吞掉了——它从未真正清理过任何进程，只让启动/停止/删除白等 4–8 秒。现在改为端口快路径（pid 文件 + 系统端口表），`POST /api/profiles/:name/start` 最坏耗时由 **7196 ms 降到 2042 ms**，而且真的能清掉残留进程。
- **端口探测去同步化**：netstat 快照缓存 + 全链异步，请求路径上不再有同步子进程。

## 📦 打包与发布链路修复

- **修复打包版自报 `0.0.0-dev`**：发布脚本原先绕过编译期版本注入，现已统一走 `scripts/build-server.mjs`；
- **修复打包版路径解析**：`MONOREPO_ROOT` 在安装布局下会上溯到安装目录之外，已增加兜底，`plugins/`、`kernels/` 不再指向无关位置；
- **前端静态资源随包发布**：便携版/安装版用浏览器打开 API 端口时，不再只看到「前端尚未构建」占位文本。
