# godsh v0.6.5

godsh — DeepSeek Harness 的图形化环境配置启动器与电影级控制中心（双模主题 · 动态极光 · 无控制台启动）。

> **这一版的主题是「说到的，就要真的做到」。**
> 上一版我们用这把尺子量出了「声明了却没生效」的字体；这一版量到了更贵的地方：
> 垫片清单里**写着**四类兼容问题、诊断里**报着**依赖树、启动流程里**说**要探活——
> 但真正出事的那一处（`negotiator` 的 `content-type`）**从来没人修**，
> 「端口通了」被当成「服务活了」，审计脚本用**子串匹配**点导航、9 条记录其实只盖住 5 个页面，却报全页达标。
> 这一版把这三件事一次性做实：**让故障在启动阶段就被说清**，**让沙箱依赖按父捆绑、组合不可拆**，
> 也让审计工具本身接受同样的验收标准。

## 🩹 启动阶段就能说清：补上真正出事的那一处垫片

dsh 的**第一个 HTTP 请求**就崩。根因不是「缺了个包」，而是**依赖树不自洽**：

`negotiator@1.x` 声明 `content-type: ^2.1.0`，但 npm 的提升算法把**顶层** `content-type` 定在了 `1.0.5`
（被 express 一线占用），而 `negotiator/node_modules` 下**又没有**嵌套副本——
于是 negotiator 在**自己的解析点上**永远拿不到合规版本，谁都没报错，直到发请求。

修法**刻意保守**，因为动别人的 `node_modules` 是最容易把事情搞大的地方：

- **只在 `negotiator/node_modules/` 下新增**一份合规副本，**顶层包一字不改**；
- **找不到可用来源就不动手**（返回 0，不猜、不造），由诊断层把话说清楚；
- **幂等**：重复执行不会产生第二份副本。

`diagnoseProfile` 同步新增同类诊断：把「声明的范围在该解析点上不成立」**连同它的后果**一起报出，并判 **CRITICAL**——
这一类问题以前是「沉默的」，现在是有结论、有定级的。

## 🔌 「端口通了」不再等于「服务活了」

新增 `probeWebUrl`：端口就绪后**先真打一次 HTTP 请求**，再宣布 running。
两个刻意的设计点：

- **带上 `Accept-Encoding: gzip, deflate, br`**——正是这个头部触发了上面那次崩溃，**不带它等于没探活**；
- **303 / 401 也算活着**（重定向与待认证都证明服务在正常响应），只把**连接重置 / 超时**判为失败。

接线覆盖**启动与重启两条路径各两处**：端口就绪后探一次，拿到带认证地址后再探一次；
任一失败即**就地跑垫片**，并把**归因写进给用户看的文案**里，而不是留一句「启动失败」让人猜。
垫片也从「特定分支才跑」改为**每次启动前都跑**，依赖树自愈成为启动的固定前置步骤。

## 📦 沙箱：依赖**按父捆绑**，组合**不可拆**

这是本版语义变化最大的一块。此前同一个沙箱依赖被多个父插件共用时**共享一份**，
父与父之间会互相踩踏；现在：

- **按父捆绑**：同一依赖被多个父共同占有时，**为每个父各建一份物理隔离副本**；
- **组合**：「根插件 + 它 `package.json` 声明的依赖」形成的**整棵子副本子树**视为**一个组合**；
- **组合不可拆**：**删母即删子、删子即删母**，不存在「留下半棵子树」的中间态；
- **唯一例外**：**子在某环境而母不在该环境**时，**保留该子并转成根条目**（否则只会留下无法解释的孤儿）；
- **反向由注入路径强制拒绝**：**母在该环境而子不在**，注入**直接拒绝**，**绝不单独放行**。

## 🐛 修掉一个真缺陷：「导入备份」曾经永远不可达

`POST /api/backup/restore` 曾被**两个语义互斥的处理者共用**：一个是「回滚环境快照」，
另一个是「导入完整备份」。前者**注册在前**，而路由分派是「命中即返回」——
于是**导入备份这条路径永远不会被执行**：前端点它只会收到「缺少 profile 或 snapshotId 参数」。

已把「导入完整备份」改为 **`POST /api/backup/import`**。**两个字面量相同的路由必须改名，
不能靠注册顺序赌运气**；前端调用侧同步更新。

## ♿ 无障碍与对比度：不达标 20 → 0

- **9 个页面 × 明暗两主题**对比度扫描：不达标 **20 处 → 0**。三类典型：浅色下**塌成中灰的空态卡**、
  写死黑底却配了低对比前景的**终端面板**、若干**临界徽章**。
- `ConfirmDialog` 补上 `role="dialog"` 与 `aria-modal="true"`——此前它只是个**视觉上的**弹层。
- **7 个页面的 19 处原生 `window.confirm`** 统一收敛到自研确认框：文案一字不改地传入，
  语义一一对应（确认 → `true`，取消 / Esc / 点遮罩 → `false`）。
  设置页那处「必须输入 `DELETE` 才继续」的 `window.prompt` **不属于** `confirm`，行为保持原样。

## 🔬 审计工具自身的缺陷也修了

页面覆盖审计原先靠**子串匹配**点侧栏导航（`'环境'` 会命中控制台、`'沙箱'` 会命中市场……），
实测 **9 条记录只覆盖了 5 个不同页面**，却报「全页达标」——**假达标**。

已改为**按 hash 路由 key** 切页 + 用 **`[data-page-container=key]` 的可见性**判定是否真到位，
全程不依赖任何文案；并且**每次都打印 `visited` 与 `distinctCount=9`** 自证覆盖，
缺页会以 `MISS:` 显式暴露，而不是被悄悄吞掉。

## ⚠️ 已知限制 / 边界

以下都是**明确边界**，不是「还没做」：

- **契约表伴随（`KNOWN_CONTRACTS`）不参与组合。** 这是需求方拍板的决定：
  契约表声明的是「跟谁一起装」的**伴随关系**，与本版定义的组合语义**不是同一维度**，
  因此它**不进入**母子树、也不受「删母即删子 / 删子即删母」管辖。
  请注意它的后果：**删除契约表声明的伴随插件，不会连带删除或保留其母条目**——
  这条边界的判定必须靠契约表自身，而不是组合树。
- **组合语义只覆盖 `package.json` 声明的依赖边**：动态 `require`、运行时按需加载、
  以及契约表补的边**不在**组合树的覆盖范围内。
- **探活只回答「进程还在吗」**：`303` / `401` 都算活着，因此**探活成功不代表功能可用**
  （例如认证 token 错误、插件内部报错仍需看日志）。这是刻意的——把「服务活着」和「业务正确」分开报。
- **垫片只在找到合规来源时才动手**：若本机确实不存在任何合规的 `content-type` 副本，
  垫片**不会**从网络下载，诊断会给出 CRITICAL 并说明原因，需要人工介入。
- **对比度达标 ≠ 全站无障碍合规**：本版覆盖的是「文本对比度 + 对话框语义 + 确认交互」三项，
  未做完整 WCAG 审计（键盘全路径、焦点陷阱、屏幕阅读器逐页实测等仍属未覆盖范围）。
- **`webKernel.defaultPort` 的删除是单向的**：旧 `config.json` 里的该字段会被**静默剥离**，
  不做迁移也不报错。环境端口来自 `findFreePort` 动态分配，内核端口来自模板（`38080`），
  两者服务的是**不同对象**，本就不该有全局默认值。

## ♻️ 升级说明

**无破坏性变更**：配置文件、环境（Profile）数据与沙箱插件全部沿用，直接覆盖安装或解压即用。

**沙箱有一个一次性的自动迁移**：首次打开时，历史上「多个父共享同一份依赖」的条目会被
**自动拆成按父隔离的副本**（空沙箱时为空操作）。迁移后每个父各自持有自己的副本，
**不会再出现「删了一个父、另一个父跟着坏」**的情况。
