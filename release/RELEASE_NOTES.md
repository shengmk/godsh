godsh — DeepSeek Harness 的图形化环境配置启动器与电影级控制中心（双模主题 · 动态极光 · 无控制台启动）。

> **这一版的主题是「说到的，就要真的做到」。**
> 上一版我们给界面写了 `Inter + JetBrains Mono`，也用真实浏览器量遍了深浅两套主题的对比度；
> 这一版顺着同一把尺子往下查，发现字体其实**从未生效**、并发提示会**互相顶掉**、
> 一个页面崩溃会**牵连整块内容区**——它们都写在代码里，却都没有真正兑现。现在兑现了。

## 🔤 字体：从「声明了却没生效」到真正内嵌

用**宽度对比法**实测（同一段中英混排文字，分别用「目标字族」与「确定的回退字族」渲染后比较像素宽度）：

| 字体 | 修复前 | 修复后 |
|---|---|---|
| `Inter` | 753.98 px = 回退宽度 → **未生效** | 786.50 px ≠ 回退 → **生效** |
| `JetBrains Mono` | 640.00 px = 回退宽度 → **未生效** | 729.61 px ≠ 回退 → **生效** |

也就是说：界面一直声明着 Inter / JetBrains Mono，但**它们并不存在**，实际渲染是 Arial 与通用等宽。
（顺带一个方法学细节：`document.fonts.check()` 对这几个字体**全都返回 `true`**——只信这个布尔型 API 会得出完全错误的结论。）

**做法**：内嵌 **Latin 变量子集**，合计约 **87 KB**。只取 Latin 是因为这两款字体本就没有中文字形——
**中文界面依然由系统字体渲染**，所以包体只增加不到 90 KB，却把拉丁字母、数字、版本号、路径、终端等等宽场景的整体观感找回来了。

- `Inter` 47.1 KB · `JetBrains Mono` 39.5 KB（均为 SIL OFL 1.1，来源与许可见 `public/fonts/LICENSE.txt`）
- `font-display: swap`：首屏文字**不会**被字体加载阻塞
- 零运行时网络请求：桌面端离线可用，也不会出现 FOUT

## 🔔 并发操作时，提示不再互相顶掉

原先每个页面各自持有一份「单槽」提示：同时在跑两个操作时，**后一条会把前一条挤掉**，
用户看不到先失败的那条——而这恰恰是上一版花大力气消灭的「失败静默」的变体。

现在改为**全局提示队列**：同一时刻最多展示 3 条，错误提示停留 6 秒（普通 4.2 秒），
并且补上了无障碍语义——`role="status"` / `aria-live="polite"`（错误用 `role="alert"` / `assertive`）
与 `aria-atomic`，屏幕阅读器终于能读到这些提示。

## 🛡️ 一个页面崩溃，不再牵连全局

原先整块内容区共用一个错误边界：**任何一页抛异常，其它已挂载页面会一起被替换成兜底界面**。
现在每个页面各自包一层（最外层保留作为最后兜底），单页故障只影响该页。

## 🎨 令牌与刻度

- 补齐间距刻度中缺失的 `--space-7: 28px`（原先把 7 跳过去了）。
- 等宽字体栈首选调整为真正内嵌的 `JetBrains Mono`。

## 🔍 顺手查清一个悬了很久的疑问

代码里长期并存两个「默认端口」：`config.webKernel.defaultPort = 3080` 与内核模板里的 `38080`。
**结论是虚惊一场**：3080 这个字段**根本没有任何消费者**（实际只读了 `allowMultiPort`），
环境端口来自动态分配 `findFreePort`，内核端口来自模板——两者服务的是**不同对象**（环境 vs 内核实例），并不冲突。
不过 3080 这个字段具有误导性，已记录待清理。

## ⚠️ 已知与说明

- 只内嵌 **Latin 子集**：中文界面的字形来自系统字体（Windows 默认中文字体），这是有意为之——
  完整 CJK 字体动辄数 MB，而桌面端系统中文渲染质量已足够。若你希望界面也统一到特定中文字体，欢迎提 issue。
- `Geist Mono` 仍会回退（我们未内嵌它），它只作为字体栈里的一个「有则更佳」的优先项，不影响实际观感。
