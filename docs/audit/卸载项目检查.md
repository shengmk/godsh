# 卸载项目检查报告（dsh Launcher v0.2.0）

> 检查方式：真实静默安装 → 检查卸载程序 → 真实卸载 → 校验残留。
> 结论：**卸载程序可被正常调用且不报错**；存在两项"设计内保留"的数据需用户知晓（见 §4）。

## 1. 卸载机制

- 安装器：NSIS（`dsh-launcher-<v>-x64-setup.exe`），安装到 `%LOCALAPPDATA%\dsh-launcher`，生成 `uninstall.exe`。
- 应用内入口：设置页「关于 → 卸载 Launcher」按钮 → `POST /api/app/uninstall`：
  1. 定位 `uninstall.exe`（exe 同目录；**便携版无此文件 → 接口返回 404，按钮不显示**）。
  2. `spawn(uninstall.exe, { detached, stdio:'ignore' })` 分离启动，主进程 1.5s 后退出。
  3. uninstall.exe（NSIS）执行：删除 exe / WebView2Loader.dll / resources/ / uninstall.exe / 桌面快捷方式 / 开始菜单快捷方式 / INSTDIR。

## 2. 实测记录（v0.2.0 安装器）

| 步骤 | 结果 |
| --- | --- |
| `setup.exe /S /D=<临时目录>` 静默安装 | exit 0；exe / WebView2Loader.dll / resources / uninstall.exe 全部落盘 |
| 检查 `uninstall.exe` 存在 | ✅ 存在 |
| 运行 `uninstall.exe /S` | **exit 0，无报错** |
| 安装目录是否清除 | ✅ 目录整体移除（含 exe、DLL、resources） |

## 3. 覆盖范围明细

**卸载程序移除：**
- 安装目录全部内容（`%LOCALAPPDATA%\dsh-launcher`）：exe、WebView2Loader.dll、resources/、uninstall.exe
- 桌面快捷方式 `dsh Launcher.lnk`、开始菜单目录

**卸载程序不涉及（设计内保留）：**
- 运行时数据 `%APPDATA%\dsh-launcher\data\`（config / kernels / allocations / unified-kernel / dsh-envs / logs）——**卸载不删用户数据**，符合预期（用户可选择「设置 → 重置」清空）
- `$DSH_HOME`（profiles / 凭据 / 会话等）——属于 dsh 本体，与 Launcher 无关
- npm 全局 dsh、npm 缓存

## 4. 发现与建议

1. **数据残留为设计行为**：卸载后 `%APPDATA%\dsh-launcher\data` 仍在（保留用户配置，便于重装恢复）。若需彻底清除，卸载后手动删除该目录，或先在应用内「重置」。
2. **卸载时环境仍在运行**：卸载只删程序文件，正在运行的 dsh 子进程会继续直到被停止（端口 4780 由后端进程持有）。建议卸载前先停止全部环境（应用内「重置」会自动停止；或手动停止）。
3. **便携版**：无卸载程序；删除解压目录即可，数据仍在 `%APPDATA%\dsh-launcher\data`（便携版数据位置与安装版相同，删除目录时一并处理）。
4. **残留检查方法**：卸载后检查 `%LOCALAPPDATA%\dsh-launcher`、注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\dsh-launcher`（NSIS 会写入卸载项，卸载时移除）、快捷方式。

## 5. 结论

- **应用可自行调用 uninstall.exe 且不报错**（实测 exit 0、目录清除）。
- 卸载干净度：程序文件 100% 移除；运行时数据按设计保留（如需彻底清除见 §4-1）。
