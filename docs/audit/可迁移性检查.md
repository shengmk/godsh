# 可迁移性检查报告（dsh Launcher v0.2.0）

> 检查范围：跨机器 / 跨用户 / 跨目录迁移、路径与环境变量、数据位置、Web 与桌面两种形态、备份恢复。

## 1. 目标平台

| 项 | 说明 |
| --- | --- |
| 首选 | Windows 10 / 11（WebView2 运行时） |
| Web 形态 | 任意带浏览器的系统，后端为 Node（`node server.mjs serve`） |
| 桌面形态 | Tauri 2（当前仅构建 Windows 目标；GNU 工具链已验证） |
| 明确不支持 | macOS / Linux 桌面构建（未配置目标，但后端与 CLI 均为跨平台代码） |

## 2. 路径与环境变量（迁移关键）

| 变量 / 配置 | 作用 | 迁移影响 |
| --- | --- | --- |
| `DSH_HOME` | dsh 根目录（profiles 所在） | **兜底顺序：`DSH_HOME` > config.dsh.home > ~/.dsh`**，换机器不会误用开发机残留路径 |
| `DSH_LAUNCHER_ROOT` | 工作区根（打包/开发） | 桌面版由 Tauri 自动设置资源目录；Web 开发模式用仓库根 |
| `DSH_LAUNCHER_DATA_DIR` | Launcher 数据目录（config/kernels/allocations/logs） | 桌面版默认 `%APPDATA%\dsh-launcher\data`；可覆盖 |
| `DSH_LAUNCHER_TEMPLATES_DIR` | 内核模板目录 | 桌面版指向资源目录；可覆盖 |
| `DSH_LAUNCHER_SERVER` | 桌面版后端入口 | Tauri 侧自动设置 |

结论：**除 `DSH_HOME` 外不依赖任何持久用户变量**；`config.json` 不写死开发机绝对路径（v0.1.4 已修）。迁移到新机器只需：安装 Node + dsh（或走"自动安装 base"）、拷贝数据目录即可。

## 3. 数据位置（迁移范围）

| 数据 | 位置 | 迁移方式 |
| --- | --- | --- |
| Launcher 配置 / 内核 / 分配 / 统一内核 / DSH 环境 | `%APPDATA%\dsh-launcher\data`（桌面）或仓库 `data/`（Web 开发） | 拷贝目录，或用「数据备份导出/导入」（JSON） |
| 运行日志 / pid / runtime.json | 数据目录内 | 随数据目录 |
| Profile 环境 | `$DSH_HOME/profiles` | 随 DSH_HOME；**不随 Launcher 数据迁移** |
| 并列 DSH 环境 | 数据目录 `dsh-envs/` | 随数据目录（本质是完整 node_modules，体积大，建议重装而非拷贝） |

**迁移建议**：新机器 → 装 Node → 装 dsh（或自动安装 base）→ 导入备份 JSON → 拷贝 `$DSH_HOME/profiles`（如需要历史环境）→ 完成。

## 4. 跨机器差异点

1. **npm 全局 dsh**：base 自愈注册依赖检测到 npm 全局实例；若新机器用其它方式安装 dsh（非 PATH/npm 全局），需在设置里登记"额外安装目录"，或直接在「DSH 环境」页安装 base。
2. **Node 版本**：≥ 20（dsh 依赖）；本机 v25。
3. **WebView2**：Windows 10 需自行安装运行时；11 自带。
4. **GNU 工具链（仅桌面构建）**：需要 MSYS2 + MinGW，且构建目录路径不含空格（见迭代日志）。
5. **编码**：所有 JSON/YAML 写入均为 UTF-8 无 BOM（历史上有 BOM 导致 serde_json / JSON.parse 失败的坑，已全部规避）。

## 5. Web 与桌面形态等价性

- 同一套后端（server.mjs）+ 同一套前端 dist；桌面版前端经 `--mode tauri` 构建（API 指向 127.0.0.1:4780），Web 版同源 `/api`。
- 差异仅在"谁拉起后端"：桌面版由 Tauri 进程托管并随窗口退出清理；Web 版手动 `node server.mjs serve`。
- **迁移切换无数据差异**（同一数据目录格式）。

## 6. 备份 / 恢复验证

- 「数据备份」导出 JSON（config/kernels/allocations/unified-kernel）→ 导入后实测恢复正确（冒烟 B1–B5）。
- Profile 目录级备份：拷贝 `$DSH_HOME/profiles` 即可；恢复后 Launcher 扫描即可见。
- 并列 DSH 环境不推荐备份（体积大、可重建）。

## 7. 结论

- **可迁移性良好**：不依赖开发机残留路径、数据目录清晰、双形态等价、提供备份/导入。
- 迁移清单见 §3 建议；已知差异点均可通过"自动安装 base / 登记目录"消化。
