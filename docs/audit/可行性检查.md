## 2. 技术可行性

- **后端**：Node.js ≥ 20 + 纯 TS ESM（tsx 直跑 / esbuild 单文件打包），无框架依赖（node:http），体积小（server.mjs ~85KB）。
- **前端**：Vite + React 18 + TS，生产构建 ~200KB（gzip ~60KB）。
- **桌面**：Tauri 2（Rust）+ WebView2；GNU 工具链可完整构建（见迭代日志的坑与解法）。
- **与 dsh 集成**：启动命令 `dsh --profile X --port P --no-open`、插件 `dsh plugin --profile X add|remove|update`、`--patch` 叠加、bundle 机制均已实测；统一内核采用 bundle 注入（`--patch` 注入单行不可行，已实测修正）。
- **多 dsh 版本并存**：base（npm 全局）+ 并列（`npm install --prefix` 独立目录），启动用 `node <entry>` 直接运行，绕开 cmd shim 进程树问题。

## 3. 性能与资源

- 界面轮询：环境 3s / 日志 2s / 安装任务 2s，单机开销可忽略。
- dsh 检测与 npm 版本查询已加 5s / 60s 缓存，避免高频轮询拖慢接口。
- 每个运行环境一个 dsh 进程 + 一条端口（默认 3080 起自动找空端口）。
- 桌面版：后端 Node 子进程常驻，内存约 50–90MB（实测）；Rust release exe 约 3.9MB。

## 5. 已知限制 / 风险（可行性边界）

1. **Windows 原生依赖文件锁**：dsh 运行中（其 sharp/koffi 原生 DLL 被进程加载）时，`npm install -g` 更新/安装 dsh 会失败（EBUSY）。已加"先停止环境再安装"的拦截；本机出现过的全局包损坏需手动重建 shim（本报告已验证恢复方法）。
2. **并列环境首次安装慢**：npm 全量下载 dsh 依赖树（数分钟），界面显示进度日志；有缓存后显著变快。
3. **插件安装依赖网络**（npm registry / 市场索引）。
4. **内容级 i18n**：市场卡片等深水区文案仍以中文为主。
5. **重置为不可逆操作**：`all`/`dsh-all` 会删除 Profile 目录/DSH_HOME，UI 已用强确认（`dsh-all` 需输入 DELETE）。

## 6. 结论

- 功能可行性：**通过**（核心功能全部实测）。
- 技术可行性：**通过**（技术栈成熟、构建链路稳定、已产出可安装发行版）。
- 剩余风险集中在**环境依赖**（dsh/Node/npm 版本、网络、Windows 文件锁），均有提示与恢复路径，不构成阻断。
