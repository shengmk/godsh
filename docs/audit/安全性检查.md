# 安全性检查报告（godsh v0.2.0，行业标准视角）

> 评估方法：威胁建模（本地桌面/Web 工具）+ OWASP Top 10（2021）映射 + 供应链与数据安全核查。
> 工具形态：本地开发/个人工具，默认只绑定 127.0.0.1，无多用户场景。

## 1. 攻击面概述

| 面 | 暴露方式 | 风险等级 |
| --- | --- | --- |
| HTTP API（4780） | 仅 127.0.0.1（默认） | 中（见 CORS 问题） |
| 插件安装/更新 | npm registry（官方）/ 本地 / git（白名单） | 中（供应链） |
| 配置文件 | 本地明文 JSON（无敏感数据） | 低 |
| 卸载/重置 | 用户主动触发（强确认） | 低 |
| 命令行参数 | 平台 shell 启动（Windows cmd） | 中（注入面，已有缓解） |

## 2. 逐项核查

### 2.1 本地绑定与认证（A01 Access Control）
- ✅ 默认 `bind 127.0.0.1`，不对外网开放。
- ⚠️ **发现：CORS `Access-Control-Allow-Origin: *`**——任意网页可向 `http://127.0.0.1:4780/api/*` 发请求（浏览器跨站读取被 CORS 放开）。攻击面：恶意网页可尝试启停环境、触发安装/卸载接口（POST 无副作用令牌）。
  - **建议（待办）**：改为同源 CORS（`Access-Control-Allow-Origin` 只回显 `Origin` 且校验为 `http://127.0.0.1:<port>` 或 `http://tauri.localhost`），或对写操作加一次性 CSRF 令牌。
- ⚠️ `serve --host 0.0.0.0` 可将 API 暴露到局域网且无认证——文档应提示仅本机使用。

### 2.2 注入（A03 Injection）
- ✅ 插件包名经 `SourcePolicy` 白名单正则校验（registry 仅 `[A-Za-z0-9._/-]`；git 需显式白名单）；Windows 下命令参数经 `quoteWinArg` 转义（`&|<>^"` 会被包裹）。
- ✅ Profile / DSH 环境名称均有正则校验（字母数字 `- _`），阻断路径穿越类输入。
- ✅ 文件写回均为白名单文件名（`config.json` / `cordis.patch.yml` 等固定名）。
- ⚠️ 残余：git 类 URL 若进入白名单且含元字符，仍依赖转义保护——建议 git 白名单仅允许 `git+https://` 官方域。

### 2.3 密钥与敏感数据（A02 Cryptographic Failures）
- ✅ Launcher 不读取、不存储、不传输 dsh 的凭据（`.credentials.yaml`、`settings.yaml` 等留在 DSH_HOME）。
- ✅ 数据文件（config/kernels/allocations）不含密钥；无静态加密需求（个人工具）。
- ✅ 所有远端交互走 HTTPS（npm registry / 市场索引）。

### 2.4 供应链（A06 / 依赖）
- ✅ dsh 与插件安装限定 npm registry（官方）+ 本地 + 白名单 git。
- ✅ pnpm `allowBuilds` 由 `security/build-permission.ts` 管理（构建脚本需授权）。
- ⚠️ 无签名/完整性校验（依赖 registry TLS）；npm 生态固有权衡，建议定期 `npm audit`（根项目）。
- ⚠️ dsh 无自动更新；Launcher 提供"检查最新版 + 一键更新"但由用户手动触发。

### 2.5 破坏性操作（A01 相关 + 可用性）
- ✅ 重置（data/all/dsh-all）有强确认：`all` 用 confirm，`dsh-all` 需**输入 DELETE**；重置前自动停止运行环境。
- ✅ 删除 Profile 前有 confirm；运行中拒绝删除。
- ⚠️ `reset dsh-all` 会删除 `config.dsh.home` 指向的整个目录——若该配置被人为改成系统目录，删除范围将扩大。建议（待办）：dsh-all 时对非默认 DSH_HOME 输出二次确认并展示完整路径。

### 2.6 配置与头（A05 Misconfiguration）
- ⚠️ 静态资源响应未加 `Content-Security-Policy` / `X-Content-Type-Options` 等安全头（内嵌前端风险低，建议补）。
- ✅ MIME 类型显式映射，未知扩展回退 octet-stream。

### 2.7 日志与信息泄露（A09）
- ✅ 日志仅含 dsh/命令输出与路径，无凭据；日志按进程/端口分文件且启动时截断。
- ⚠️ 错误响应会回显内部异常文本（`err.message`）——本地工具可接受；若未来暴露到局域网需收敛。

## 3. OWASP Top 10（2021）映射结论

| 条目 | 状态 |
| --- | --- |
| A01 访问控制 | ⚠️ 本机绑定 OK，CORS * 需收紧 |
| A02 加密失败 | ✅ 无敏感存储；传输全 HTTPS |
| A03 注入 | ✅ 白名单 + 参数转义（残余 git URL 建议收紧） |
| A04 不安全设计 | ⚠️ 破坏性操作已有强确认，dsh-all 路径确认待补 |
| A05 配置错误 | ⚠️ CORS/安全头待补 |
| A06 脆弱组件 | ⚠️ 依赖跟踪 + audit 建议 |
| A07 认证失败 | ✅ 本机无认证场景（绑定 127.0.0.1） |
| A08 软件与数据完整性 | ⚠️ 依赖 registry TLS，无签名 |
| A09 日志 | ✅ 无敏感信息泄露 |
| A10 SSRF | ✅ 远端请求仅市场索引固定 URL 与用户显式输入；无跳转代理 |

## 4. 修复优先级建议

| # | 项 | 优先级 | 建议 |
| --- | --- | --- | --- |
| 1 | CORS 收紧 | 高 | 同源/白名单回显，写操作防跨站 |
| 2 | dsh-all 目标路径确认 | 中 | 展示将被删除的完整路径 + 输入 DELETE |
| 3 | 安全响应头（CSP 等） | 中 | 静态响应补头 |
| 4 | git 白名单收紧 | 低 | 仅官方域 |
| 5 | `npm audit` 纳入 CI | 低 | 发布前执行 |

## 5. 结论

- 作为**仅绑定本机、无多用户、无远端管理**的个人工具，整体安全姿态可接受；无已知可利用的高危漏洞。
- 需修复项集中在 **CORS 跨站调用面（高）** 与**破坏性操作的路径确认（中）**，建议下一迭代优先处理；其余为加固建议。
