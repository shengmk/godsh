# godsh 插件仓库沙箱（Plugin Vault）功能优化方案

> **文档版本**：v1.0.0  
> **适用版本**：godsh v0.5.1 ~ v0.6.0  
> **作者**：Antigravity Agent  
> **状态**：已落地第一阶段，进入架构演进与深水区优化

---

## Executive Summary（执行概要）

在早期的 DeepSeek Harness 生态中，由于官方 DSH 缺乏全局插件仓库管理机制，用户通常通过创建名为 `plugin_bag` 或 `pluginsbag` 的专用 Profile 来充当“插件临时收纳袋”。这种做法带来了诸多架构隐患：
1. **磁盘冗余与碎片化**：每个环境各自 `npm install`，动辄几十兆到上百兆的依赖在不同 Profile 中重复下载与解压；
2. **环境串扰与脆弱性**：临时 Profile 的 `node_modules` 扁平化安装极易破坏依赖树，导致核心服务（如官方 DSH 升级后）解析崩溃；
3. **分发效率极其低下**：用户想要在新环境使用已下载的插件，必须重新经历漫长的网络拉取与编译构建。

**本次已完成的核心动作**：
已成功扫描系统中所有环境（包括 `plugin_bag`、`web`、`dshcoding`、`desktop`、`manage` 等），**将全部 59 个已下载 Bundle 插件完整迁移沉淀至 godsh 的 Plugin Vault（沙箱中枢）**，建立了双端元数据索引（`%APPDATA%\godsh\data\vault.json` 与工作区 `data/vault.json`），并固化了本地包寻址路径。

本文档在此坚实基础上，提出系统性的**沙箱功能深度优化方案**，推动沙箱由“静态存储容器”进化为具备**零拷贝瞬时挂载、内核自愈垫片伴随、多版本安全隔离、全自动垃圾回收与智能安全审计**的企业级插件运行中枢。

## 二、 沙箱五大深度优化方案（Deep Optimizations）

### 优化 1：NTFS Directory Junction 零拷贝瞬时挂载与热插拔 (Zero-Copy Instant Mounting)

#### 当前现状与瓶颈
目前 `deployToProfile` 主要是将插件写入目标 Profile 的 `package.json` 并维护 `bundles` 数组，随后仍需依赖 npm/pnpm 解析安装或查找全局软链。如果网络不稳或存在环境依赖锁，会导致部署耗时延长。

#### 优化方案
1. **纯 Windows 原生 Junction 软链直通**：
   - 当用户从沙箱点击 **「🚀 瞬时注入」** 时，直接在目标环境的 `profiles/<profile>/node_modules/<pkgName>` 上建立指向 `vault_store/<pkgName>@<version>` 的 **NTFS Directory Junction**（使用 Windows 原生 `mklink /J` 或 Node.js `fs.symlinkSync(target, dest, 'junction')`）。
   - **速度提升**：从原先的 15~45 秒下载解压，缩短至 **< 10 毫秒**完成挂载！
2. **跨环境物理单实例（Single-Instance Storage）**：
   - 无论用户创建了 5 个还是 10 个 Profile，同一个版本的插件在磁盘上仅保留一份只读副本，彻底根除磁盘占用恶性膨胀。
3. **热拔插（Live Hot-Unplug）**：
   - 结合 Cordis 动态卸载，断开 Junction 链接并自动从内存与 `cordis.patch.yml` 中剥离该插件，无需重启 Profile 服务。

### 优化 2：智能依赖伴随与生态自愈契约矩阵 (Companion & Auto-Healing Shims)

#### 痛点剖析
如我们近期解决的 DSH 0.1.2 破坏性升级（`installSettingsSection` 丢失、`settingsNamespace` 更名、`CallId -> ToolCallId`、`undici 8` 移除 `wrap-handler.js`），老旧插件直接挂载进新内核极易引发 ESM 动态导入致命异常退出。

#### 优化方案
将沙箱打造成**自带免疫力的自愈系统**，建立双向契约矩阵：

```typescript
// 智能契约配置中心 (packages/plugin-registry/src/vault-contract.ts)
export interface VaultContract {
  // 必须伴随注入的配对插件
  companions?: { pkg: string; version: string; isBundle: boolean }[]
  // 该插件所需的兼容垫片类型
  requiredShims?: ('settings-namespace' | 'llm-callid' | 'undici-handler' | 'model-selection')[]
  // 冲突互斥规则
  conflictsWith?: string[]
  // 最低/最高官方 DSH 内核限制
  dshEngineRange?: string
}
```

1. **自动联动安装**：
   - 注入 `dsh-web-search-pro` 时，沙箱自动级联挂载 `@anweat/dsh-browser`，无需用户手工寻找。
2. **伴随垫片自动就绪**：
   - 沙箱在挂载插件到 Profile 时，自动触发 `ensureCompatibilityShims()`，确保宿主 Node.js/DSH 无论处在 0.1.1 还是 0.1.2，都能无感向下兼容运行。
3. **互斥探测与保护**：
   - 自动检测并阻止互斥插件（如两个深度修改侧边栏的同类插件）同时注入，并在 UI 给出友情警示。

### 优化 3：多版本共存、灰度测试与一键快照回滚 (Multi-Version & Atomic Rollback)

#### 优化方案
1. **多版本并存池**：
   - `vault_store` 目录统一遵循语义化命名：`vault_store/@org_pkg@1.0.0`、`vault_store/@org_pkg@1.1.0`。
   - 用户可以在沙箱中自由保留稳定版与测试版插件。
2. **版本原子切换（Atomic Pointer Switch）**：
   - 当用户升级某环境中的插件时，沙箱通过重定向 Junction 连接点实现秒级版本切换。
3. **健康度守卫与自愈回滚（Health Guard & Auto-Rollback）**：
   - 升级后启动 Profile，若在 10 秒内检测到该插件抛出致命异常（通过 `diagnoseStartFailure` 捕获），沙箱立即自动回退 Junction 指向上一稳定版本，并向桌面通知发出告警，实现**零中断运行**。

---

### 优化 4：静态安全审计与权限防御隔离 (Security Sandbox & Permission Guard)

#### 优化方案
为了防止第三方未审核插件存在恶意代码、越权扫描用户敏感文件或私自窃取 API Key：
1. **静态 AST 预检（Pre-Stage Static Audit）**：
   - 插件入沙箱时，自动解析代码 AST 语法树，检测敏感特征：
     - 是否存在 `process.env` 大范围遍历窃取凭证；
     - 是否探测 `~/.ssh`、`~/.dsh/.credentials.yaml` 等敏感密钥路径；
     - 是否包含未经声明的不可信内网反弹 Shell 或恶意外联请求。
   - 在前端卡片打上安全评级标签：`🛡️ 官方精选` · `🟢 安全认证` · `⚠️ 需申请网络/本地系统权限`。
2. **权限声明文件（`dsh-permission.json`）**：
   - 推动社区建立统一的权限规范契约，沙箱可对高危插件启用 Node.js 细粒度权限管控标志（如 `--allow-fs-read`、`--deny-net`）。

### 优化 5：前端沙箱控制中心独立化与极客交互 (Dedicated Vault Hub UI)

#### 优化方案
1. **左侧新增独立一级导航「📦 插件沙箱 (Vault Hub)」**：
   - 不再局限于“插件市场中的一个状态标签”，而是拥有专门的集中管理看板。
2. **沙箱控制台看板功能**：
   - **全局统计概览**：已归档插件总数（59）、总节省磁盘空间（如已节省 1.8 GB）、已部署 Profile 关联图。
   - **一键提取与反向同步（Harvest from Profiles）**：自动检测各 Profile 中用户自行用命令行安装的新插件，一键“收割”归档至沙箱。
   - **批量挂载阵列**：勾选多个插件，下拉选择多个目标 Profile，一键执行**广播式批量注入**。
   - **沙箱体检与大扫除（Vault Garbage Collect）**：一键扫描并清理无任何 Profile 引用、且已被新版本替代的历史孤立包。
