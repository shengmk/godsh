## Bug1：环境无法启动（P0，必修）

### 现象
- 「环境管理」页点启动 → 进程提前退出，日志报 `dsh: failed to parse overlay ...cordis.patch.yml: YAMLException: bad indentation of a mapping entry (2:11)`

### 根因（双层）
1. **patch 序列化缺引号**（launcher 自身 bug）
   - `packages/profile-manager/src/patch.ts` 的 `serializePatchList` 写 `- id: @deepseek-ai/dsh-base`（裸值）
   - 新版 dsh（0.1.1-rc.2）的 YAML schema 把 `@` 开头裸值当作特殊标记 → 解析报 "bad indentation"
   - **已修复**：新增 `quoteIdIfNeeded()`，`@`/`!`/`$` 开头或含特殊字符的 id 加双引号（`- id: "@deepseek-ai/dsh-base"`）；并修复了现有 `web`/`plugin_bag` 的 patch 文件
2. **DSH Desktop 官方 bundle junction 断链**（环境级问题，launcher 需自愈）
   - `~/.dsh/profiles/node_modules/@deepseek-ai/*` 是 Junction，目标指向 `...\resources\app.asar\node_modules\@deepseek-ai\dsh-base`
   - asar 是文件不是目录 → junction 永远解析失败 → 加载 bundle 时报 `plugin tree failed to load`
   - 影响：任何引用官方 bundle（dsh-base/dsh-web-app）的 profile 都无法启动
   - **launcher 自愈方案**：启动任一 profile 前检测 fallback 中官方 bundle 是否可解析；不可解析时从 asar 提取真实包到 `profiles/node_modules/@deepseek-ai/`（真实目录替代断链 junction），或重建 junction 指向 asar 内虚拟路径（用 Electron require 验证可行性后选一）

### 修复清单
- [x] D1: patch.ts `quoteIdIfNeeded` 序列化（已完成，见上）
- [x] D2: 现有损坏 patch 文件修复工具（一键修复 web/plugin_bag/desktop）
- [x] D3: 启动自愈：start 前校验官方 bundle 可解析，缺失/断链时自动修复（提取 asar 内包）
- [x] D4: 启动失败时错误信息友好化（直接展示 dsh 日志关键行，而非"进程提前退出"）

## Bug2：插件分配页增加「卸载」选项（P1）

### 现象
- 分配页已有「移除」= 从分配列表（cordis.patch.yml）拿掉，但**插件仍装在环境里**
- 用户想要：在分配页直接**卸载**（真正删除依赖 + node_modules）

### 方案
- 分配行右键菜单 + 行内按钮新增「卸载」：调 `dsh plugin --profile <env> remove <pkg>`
- 卸载成功 → 同时移除分配记录 → 刷新
- 二次确认弹窗（防误删）；卸载失败显示错误类型（复用市场页的 classifyPluginError）
- 复用现有 `POST /api/profiles/:name/plugins { action: 'remove', pkg }` 接口

### 修复清单
- [x] E1: api.ts 暴露 `uninstallFromProfile(profile, pkg)`
- [x] E2: AllocationsPage 右键菜单 + 卡片按钮加「卸载」+ 确认框
- [x] E3: 卸载成功后同步移除分配 + 刷新

## Bug3：主界面过慢（P1）

### 现象
- 打开应用/切换页面有明显卡顿，尤其环境多时

### 根因
- `profileView` 每次调用都执行 `profileStatusView` → `isPortListening`（netstat 子进程），
  `GET /api/profiles` 对每个 profile 串行做端口检查，profile 多 + 3s 轮询时开销大
- 前端每次切换页面都会重新请求 `/api/profiles` + `/api/plugins` + `/api/kernels`

### 方案
- **端口状态缓存**：`isPortListening` 结果缓存 2s（进程刚启动/停止的场景由主动失效兜底）
- **合并状态轮询**：已存在 `/api/profiles/status?names=`，把 Dashboard/Profiles 轮询改用合并接口，避免逐卡请求
- **前端数据复用**：App 层 `profiles` 缓存 + 页面挂载复用（不重复 fetch）
- **懒加载确认**：确认 7 页 `React.lazy` 生效，首屏只加载 Dashboard

### 修复清单
- [x] P1: `isPortListening` 2s 内存缓存（netstat 只跑一次/2s）
- [x] P2: ProfilesPage/Dashboard 轮询改走合并 `/api/profiles/status?names=`
- [x] P3: App 层 profiles/plugins/kernels 缓存，页面切换不重拉
